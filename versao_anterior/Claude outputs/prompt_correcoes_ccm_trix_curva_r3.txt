ITEM 1 — Repositório git incompleto (BLOQUEANTE)
======================================================================
Problema constatado: a pasta .git entregue contém apenas
refs/heads/master e logs/HEAD. Não existem HEAD, config nem objects/.
Isso não é um repositório git funcional — comandos básicos como
`git log`, `git show <hash>` e `git ls-files` falham com "fatal: not
a git repository". Como consequência direta, auditar_seguranca.py
(portão de segurança) também falha de cara, porque depende de
`git ls-files`.

O que fazer:
- Reempacotar o projeto de forma que a pasta .git enviada seja um
  repositório git real e íntegro (com HEAD, config, objects/, refs/),
  não apenas uma cópia parcial de subpastas internas.
- Confirmar rodando, na pasta entregue, ANTES de gerar o pacote final:
    git status
    git log --oneline
    git show --stat HEAD
  Os três comandos têm que funcionar sem erro.
- Se o método de empacotamento for zip/cópia manual de pasta, incluir
  a pasta .git inteira (não filtrar arquivos "invisíveis" ou ocultos
  do sistema operacional na hora de compactar).

ITEM 3 — Verificação SSL desabilitada em ingestao_cepea.py (CORREÇÃO)
======================================================================
Problema constatado: em ingestao_cepea.py, a função _criar_ssl_context()
desativa a verificação de certificado e de hostname:
    ctx.check_hostname = False
    ctx.verify_mode = ssl.CERT_NONE
Isso expõe as duas fontes de coleta do RTCNI (CEPEA/ESALQ e Notícias
Agrícolas) a um ataque man-in-the-middle capaz de servir uma página
HTML fabricada sem que o código perceba. O preço RTCNI classificado
como "MEDIDO" alimenta a Watchlist e o cálculo de convergência/spread
usados em decisão de trade — não é um dado meramente informativo, então
o risco de integridade do dado é real, mesmo sendo baixa a probabilidade
de exploração.

O que fazer:
- Remover as duas linhas citadas e usar o contexto SSL padrão retornado
  por ssl.create_default_context() sem alterações (ou remover a função
  _criar_ssl_context() por completo e usar o contexto default direto
  nas duas chamadas de urllib.request.urlopen).
- Confirmar que as duas fontes (CEPEA/ESALQ e Notícias Agrícolas)
  continuam respondendo normalmente com a verificação de certificado
  ativa. Se algum dos dois domínios apresentar erro de certificado
  legítimo (expirado, cadeia incompleta), reportar isso explicitamente
  no relatório de entrega em vez de reintroduzir o bypass.
